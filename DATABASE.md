# Database

PostgreSQL 18. Schema managed exclusively by Flyway (`src/main/resources/db/migration`).
Never modify a schema manually, and never edit a migration that has been applied anywhere.

## Migrations

| V1 | `V1__baseline.sql` | Baseline; no tables. Establishes the migration pipeline. |
| V2 | `V2__create_app_user.sql` | `app_user`, `app_user_role` (platform roles only) |
| V3 | `V3__create_refresh_token.sql` | `refresh_token` (hashed, rotating refresh tokens) |

## Tables

### app_user
| Column | Type | Notes |
|---|---|---|
| id | UUID | PK, generated by the application |
| email | VARCHAR(254) | unique; stored lower-case (`ck_app_user_email_lowercase`) |
| password_hash | VARCHAR(255) | `{bcrypt}...` (algorithm-prefixed, upgradeable) |
| first_name, last_name | VARCHAR(100) | |
| status | VARCHAR(20) | ACTIVE, BLOCKED, DELETED. Users are never physically deleted. |
| created_at, updated_at | TIMESTAMPTZ | UTC |
| version | BIGINT | optimistic locking |

### app_user_role
`(user_id, role)` PK. Roles: `OWNER`, `SYSTEM_ADMIN`. Garage roles are not stored here (see ARCHITECTURE.md).

### refresh_token
| Column | Type | Notes |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK app_user |
| family_id | UUID | one family per login session; indexed |
| token_hash | VARCHAR(64) | SHA-256 hex of the opaque token; unique. The raw token is never stored. |
| created_at, expires_at | TIMESTAMPTZ | |
| revoked_at | TIMESTAMPTZ | null = active |
| replaced_by_id | UUID | FK refresh_token: rotation chain |
| version | BIGINT | optimistic locking |

## Conventions

- Singular, snake_case table names (`app_user`, `repair_event`); `user` is reserved in PostgreSQL.
- `id UUID` primary keys, generated by the application.
- `TIMESTAMPTZ` for instants (`created_at`, `updated_at`), always UTC. `DATE` for calendar dates.
- Enums stored as `VARCHAR` with a `CHECK` constraint (readable, easy to extend via migration).
- Named constraints: `pk_<table>`, `fk_<table>_<column>`, `uk_<table>_<columns>`,
  `ix_<table>_<columns>`, `ck_<table>_<rule>`.
- Foreign keys always declared; indexes created for every FK used in lookups.
- Historical data (repair events, mileage, audit) is append-only: no `ON DELETE CASCADE`.

## Local operations

```bash
docker compose up -d                                   # start
docker exec -it repairtrack-postgres psql -U repairtrack -d repairtrack
docker compose down -v                                 # stop and DELETE all local data
```
